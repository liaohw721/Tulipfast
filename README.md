# TulipFast

**TulipFast: Accelerating Robot AI Inference by Adaptive Vision Feature Reuse**

TulipFast is a small, reproducible proof of concept exploring whether a vision encoder can avoid repeated computation by reusing previously calculated image features. The current repository contains three separate experiments; their results should not be treated as interchangeable.

## What each script tests

| File | Experiment | Important limitation |
|---|---|---|
| `app.py` | A small, randomly initialized synthetic VLA-style model. It compares running the whole model with reusing vision features for a fixed input. | It is not a pretrained VLA model or a robot policy. The input is synthetic and does not change. |
| `vision_test.py` | Measures pretrained ResNet-18 feature-extraction latency on `test_image.jpg`. | This is a single-image encoder timing test, not a caching benchmark. |
| `adaptive_test.py` | Compares `Always Refresh`, `Fixed Rate`, and `Adaptive Cache` using pretrained ResNet-18 and a generated sequence of perturbed image tensors. | The sequence is made by adding independent noise to one transformed photo. It is not real camera video, and feature error is not robot-action accuracy. |

The current prototype runs on the CPU. It has **not** been deployed to ASUS UGen300 hardware and does not control a real robot.

## Setup (Windows)

Open a terminal in the project folder:

```powershell
python -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

The first run of `vision_test.py` or `adaptive_test.py` may download the pretrained ResNet-18 weights, so an internet connection may be required. `app.py` uses its own randomly initialized synthetic model.

## Run the experiments

Launch the interactive synthetic-model demo:

```powershell
streamlit run app.py
```

Measure pretrained ResNet-18 feature-extraction latency:

```powershell
python vision_test.py
```

Run the three caching strategies:

```powershell
python adaptive_test.py
```

`adaptive_test.py` accepts optional settings. For example:

```powershell
python adaptive_test.py --frames 30 --trials 5 --refresh-interval 10 --threshold 0.02 --num-threads 2 --seed 42
```

Use `python adaptive_test.py --help` or `python vision_test.py --help` to see all options. Relative image and output-directory paths are resolved from the project folder, so the scripts can be launched from another working directory.

Run the lightweight cache-logic tests (these use a tiny fake model and do not download ResNet weights):

```powershell
python -m unittest discover -s tests -v
```

## Results and interpretation

Both benchmark scripts save timestamped CSV files in `results/`. The adaptive benchmark saves:
- `fair_raw_*.csv`: each strategy's result for each trial, including settings and software versions.
- `fair_summary_*.csv`: summary statistics, cache hit rate, feature error, and speedup relative to `Always Refresh`.

The repository contains multiple historical runs. For example:

- The archived `optimization_summary_20261012_201639.csv` reports a median of `0.164875 ms` for the synthetic baseline and `0.074150 ms` for cached vision, or about `2.22×`. This result belongs only to the fixed-input synthetic-model experiment.
- The archived `fair_summary_20261013_203643.csv` reports about `1.41×` speedup for Adaptive Cache and `10.58×` for Fixed Rate relative to Always Refresh. Fixed Rate also has larger feature error in that run, illustrating the speed-versus-fidelity trade-off.

These are **historical example runs**, not a guarantee of what a new run will measure. CPU timing varies by machine and system load. Re-run the benchmark and use the CSV generated by that run when reporting results. Do not compare the ratios from `app.py` and `adaptive_test.py` as if they measured the same workload.

## Current limitations and next steps

- Test with real consecutive camera frames rather than noise-perturbed tensors.
- Evaluate cache thresholds against a task-level metric, not only feature difference.
- Record hardware, environment, and repeatable benchmark artifacts for every reported result.
- Explore compatible edge-accelerator deployment only after validating the model and runtime on the target hardware.
